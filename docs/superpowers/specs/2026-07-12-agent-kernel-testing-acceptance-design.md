## 1. 章节职责

第四章回答：

> 如何用确定性测试和真实对话两条轨道，证明每个模块既符合协议，又能在真实 Agent 链路中承担职责？

核心方法：

> 一个模块，一份合同，一个真实场景，一次累计回归。

## 2. 方案选择

已确认采用双轨验证模型：

```text
确定性验证
  -> Unit
  -> Contract
  -> Architecture

真实链路验证
  -> Real Model Smoke
  -> Kernel Integration
  -> Progressive Real Dialogue
  -> Application E2E（后续）
```

传统测试金字塔不能准确表达真实对话是每个模块完成门禁；单纯验收矩阵也不足以解释不同测试方法的职责。

## 3. 测试替身边界

测试替身只允许覆盖确定性输入、错误和状态转换，不能替代主要真实验收。

禁止使用模拟 Model、固定 Tool Call、预填 Memory、预填 Workflow 分支或固定最终答案证明模块完成。

## 4. 模块完成公式

```text
模块完成
  = 确定性测试通过
  + 当前真实对话通过
  + 历史真实对话回归通过
  + 架构边界通过
  + 证据完整
```

状态只允许：

```text
PASS
FAIL
BLOCKED
NOT RUN
```

`BLOCKED` 和 `NOT RUN` 不能视为通过。

## 5. 场景与映射

`K-001` 至 `K-010` 负责协议、边界和 Kernel 能力验收；`RD-001` 至 `RD-012` 负责真实用户输入驱动的累计链路验收。

每个实现任务必须关联对应 K 和 RD。纯 Architecture Test 基座任务只关联 K-009，不声明模块完成。

## 6. 边界

本次确认不改变：

- RD 固定输入和主要断言。
- 真实 Provider 要求。
- 累计回归门禁。
- 六个核心原语。
- 当前不得创建代码目录。

本次确认只完成第四章设计，不代表第五章及后续章节已经通过本轮逐章审查。
