## 2. 变更原因

原第三章同时描述技术原则、Model 与 Workflow 协议字段、Adapter、Execution、配置、可观测性和实施顺序，技术选择与模块设计边界不清晰。

作为自学 Agent 框架的项目，第三章首先需要回答哪些核心机制必须亲手实现、哪些通用基础设施应当复用，以及为什么采用当前最小技术组合。

## 3. 新增内容

- 技术选择的八项判断标准。
- Agent Kernel 核心机制的自研范围。
- Provider 通信、Schema、测试和工程工具的复用范围。
- Python 3.11、`uv`、异步边界和类型表达策略。
- 结构化、可序列化、Provider Neutral 的公共协议方向。
- 第一阶段 Adapter 的选择理由、限制和替换边界。
- 配置、凭证、失败透明和 Provider 隔离规则。
- 需要延后确认的技术选项和重新评估时点。

## 4. 修改内容

第三章调整为：

```text
3.1 技术选型目标与判断标准
3.2 自研与复用边界
3.3 Python 工程与异步执行基线
3.4 公共协议与结构化数据策略
3.5 第一阶段 Adapter 选择
3.6 配置、凭证与 Provider 隔离
3.7 可观测性与测试工具策略
3.8 第一条纵向切片技术基线
3.9 延后决定的技术选项
```

具体模型名称不再作为架构常量，模型标识由 `ANANHU_REAL_MODEL` 在运行时提供，并记录在测试证据中。

## 6. 受影响内容

## 7. 测试和验收

- 第三章能够区分核心机制自研和通用工具复用。
- 每项第一阶段技术选择说明理由、限制和替换边界。
- 尚未确认的 SDK、Schema 库和 Provider 能力映射明确标记为待确认。
- `ModelRequest`、`ModelResponse`、`WorkflowState` 和 Execution 细节仍能在第五章找到。
- 具体模型 ID 不再作为 Kernel 架构事实。
- 文档版本、索引、标题层级和关联链接保持一致。
