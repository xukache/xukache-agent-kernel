## 2. 变更原因

当前分支与旧 `mvp`、`main` 项目彻底分离。旧项目继续保留在原分支，本分支从空白起点建立通用 Agent Kernel，不再兼容或迁移旧实现。

## 3. 删除内容

本分支删除旧项目的：

- 业务和基础设施代码。
- 测试、数据和配置。
- CLI、TUI、Runtime、Tool、Prompt、Storage 和 Evaluation。
- 旧架构正文、API 契约、后端规范和实施计划。
- 旧模型目录、旧业务规格和旧运行产物。

## 4. 保留内容

只保留新重构所需的：

- `DEV_SPEC.md` 当前完整开发规格。
- `docs/dev-spec/` 开发规格版本规则。
- `docs/superpowers/specs/` 新 Kernel 设计确认记录。
- 新架构版本目录规则。
- 基础环境和仓库管理文件。

## 5. 新项目规则

- Kernel 只保留 `Agent`、`Workflow`、`Tool`、`Memory`、`Model`、`Runtime` 六个核心原语。
- 业务以后放在 `applications/`，不反向进入 Kernel。
- 旧项目不作为接口、数据模型、测试或迁移来源。
- 完整开发规格持续维护在根目录 `DEV_SPEC.md`。
- 每个版本的新增和修改记录在 `docs/dev-spec/versions/`。
- 改变系统边界时，再创建 `docs/architecture/versions/` 下的完整架构版本。

## 6. 兼容性

本版本明确不提供旧项目兼容层，不保留旧模块别名、旧数据协议或旧入口。

## 7. 验收标准

- 当前分支不再包含旧业务代码和旧计划。
- 当前分支不再以旧架构文档作为事实源。
- 新规格可以独立解释 Kernel 的目标和边界。
- 后续模块确认可以从 `Agent` 开始逐项进行。
