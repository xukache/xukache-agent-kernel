## 2. 变更原因

原第六章只有阶段总览和简短进度表。任务隐藏在表格中，文档目录无法展示完整实现路径，也无法直接回答：

- 每个阶段具体实现哪些机制。
- 任务之间有什么依赖。
- 每一步学习什么。
- 每个任务如何验收。
- 什么时候可以进入下一阶段。

参考文档通过把每个任务提升为标题，让目录本身成为施工地图。本版本采用同样的表达方法，但不提前冻结尚未确认的文件路径和 Python 类名。

## 5. 关键调整

- 旧 A1-A10 文档修订记录退出项目排期，继续由第九章版本历史维护。
- 第一阶段排期止于通用 Kernel 完成和首个架构版本发布。
- Application、Interface 和业务 Evals 回到第七章扩展路线。
- Streaming、Cancellation、Hooks、Guardrails、Retry 等独立机制拆成独立任务。
- 每个 Core 都有协议任务、实现任务和真实对话出口任务。
- 每个阶段结束后必须回归此前全部 RD。
- 详细文件、类、方法和 pytest node 由确认后的实施计划维护。

## 8. 验收标准

- 第六章目录能够显示 47 个任务标题。
- 阶段总览、进度表、详细任务和里程碑使用同一组 A-H 编号。
- 每个详细任务都有学习问题、依赖、交付、验收和关联。
- 47 个任务没有重复 ID 或缺失 ID。
- 每个 RD 都有明确阶段出口任务。
- Application 和 Interface 不再出现在第一阶段实施任务中。
- 旧 A1-A10 文档修订历史不再作为开发任务。
- 物理路径和最终 Python 签名保持待确认。

## 9. 架构版本影响

本版本调整实施路线和任务表达，不改变系统边界、依赖方向或运行链路，不需要创建新的架构版本正文。
