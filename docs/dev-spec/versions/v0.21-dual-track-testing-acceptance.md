## 2. 变更原因

原第四章把 Unit、Contract、Architecture、Integration、Real Model、Kernel E2E 和 Progressive Real Dialogue 放在同一测试分层中，导致 Kernel Integration、E2E 和 RD 场景职责重叠。

本版本采用双轨验证：确定性测试证明协议与边界，真实对话证明模块在真实累计链路中承担职责。

## 3. 新增内容

- 确定性 TDD 与真实场景驱动验收的区别。
- 确定性验证和真实链路验证两条轨道。
- 测试替身允许与禁止范围。
- Kernel 累计集成与产品 E2E 的边界。
- `PASS`、`FAIL`、`BLOCKED`、`NOT RUN` 状态语义。
- K 与 RD 的模块完成映射。
- 真实运行的最小证据和失败复现字段。
- 不依赖任意百分比目标的质量事实基线。

## 4. 修改内容

第四章调整为：

```text
4.1 测试是学习和实现契约
4.2 双轨验证模型
4.3 测试替身使用边界
4.4 确定性测试
4.5 Kernel 累计集成测试
4.6 渐进式真实对话验收
4.7 断言与证据规则
4.8 模块验收映射
4.9 测试执行与 CI
4.10 质量与性能基线
```

第一阶段不再使用“Kernel E2E”名称；没有业务 Application 和正式 Interface 时，完整 Kernel 链路属于累计集成或 Kernel 验收。

## 5. 场景保留

`RD-001` 至 `RD-012` 的固定原始输入、模块职责和关键断言继续保留。场景展示被压缩，但不改变：

- 真实 Provider 要求。
- Tool Choice 能力门禁。
- Memory 来源追踪。
- Streaming 实际增量要求。
- Cancellation 下游停止要求。
- Workflow 并行重叠要求。
- Retry 同一幂等键要求。
- 历史场景累计回归规则。

## 6. 受影响内容

- `DEV_SPEC.md` 第四章。
- `DEV_SPEC.md` 目录、阶段 A、版本记录和阅读顺序。
- `docs/dev-spec/README.md` 当前版本与索引。
- Agent Kernel 重构设计记录。

不改变：

- `K-001` 至 `K-010` 的能力范围。
- `RD-001` 至 `RD-012` 的真实验收范围。
- 真实 Model 不得被模拟输出替代的规则。
- 六个核心原语和运行链路。
- 当前实现准入门禁。

## 7. 测试和验收

- 第四章清晰区分确定性测试和真实链路验证。
- 测试替身规则能够判断允许和禁止场景。
- Unit、Contract、Architecture、Integration 和 RD 的职责不重叠。
- 每个模块能够映射到对应 K 和 RD。
- `NOT RUN`、`BLOCKED` 不会被标记为通过。
- RD 固定输入和关键断言仍存在。
- 文档版本、索引、标题层级和关联链接保持一致。

## 8. 架构版本影响

本版本调整测试组织和完成门禁表达，不改变模块职责、依赖方向或运行链路，不需要新增架构版本正文。
