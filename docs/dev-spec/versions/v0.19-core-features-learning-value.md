## 2. 变更原因

原第二章名为“核心特点”，实际包含十八节模块边界、支撑协议、外围能力、验收视图和设计取舍，正文约四百余行。章节内容专业但职责过载，并与第五章模块设计和第八章模块确认记录重复。

本版本将第二章恢复为项目能力概览，只展示最重要的设计特点，并说明每项特点解决的工程问题和对应的学习价值。

## 3. 新增内容

- 说明六个核心原语如何建立 Agent 框架的最小心智模型。
- 展示从用户输入到 Result 和 Events 的完整执行闭环。
- 将组合式架构与单向依赖关联到学习目标。
- 说明 Adapter 可替换的目的不是堆叠 Provider，而是验证公共协议。
- 将结构化结果和运行事件解释为观察 Agent 内部过程的手段。
- 将渐进式真实对话验收解释为模块验证与学习工具。
- 展示从通用 Kernel 扩展到业务 Application 的路径。

## 4. 修改内容

第二章由十八节收敛为七节：

```text
2.1 六个原语建立最小心智模型
2.2 从输入到结果的完整执行闭环
2.3 组合式架构与单向依赖
2.4 Adapter 驱动的全链路可替换
2.5 结构化结果与可解释运行过程
2.6 渐进式真实对话验证
2.7 从通用 Kernel 扩展到业务 Application
```

统一表达路径为：

```text
特点是什么
  -> 为什么这样设计
  -> 可以观察到什么
  -> 能从中学到什么
```
