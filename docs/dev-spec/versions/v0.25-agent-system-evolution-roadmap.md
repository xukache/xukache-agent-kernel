## 2. 变更原因

原第七章主要描述如何新增 Agent、Workflow、Tool、Provider 和 Interface，与第五章的模块边界和扩展规则重复，无法清楚回答 Kernel 完成后如何成长为真正的 Agent 系统。

原第 8-10 章属于确认记录、版本治理和文档导航，放在完整开发规格末尾造成主线过长，也与已有目录职责重复。

## 3. 新增内容

第七章重构为：

```text
Kernel 能力边界
  -> 可复盘的 Agent Harness
  -> 首个垂直业务 Application
  -> 单 Agent 与 Multi-Agent 基线实验
  -> 完整证据闭环
  -> 复杂能力准入门禁
```

新增的关键规则：

- Kernel 完成不等于业务 Agent 产品完成。
- Harness 通过控制面、状态面和证据面补齐运行治理。
- Session、WorkflowState、Durable Memory 和 Checkpoint 必须分离。
- 每次 Run 逐步形成状态、Trace 和聚合报告三类工件。
- 首个业务 Application 必须建立真实小闭环和单 Agent 基线。
- Multi-Agent 必须用相同评测集证明收益。
- 量化结论必须能够追溯到版本、配置、任务和运行工件。
