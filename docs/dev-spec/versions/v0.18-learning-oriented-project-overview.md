## 2. 变更原因

原第一章以工程交付和架构约束为主要叙事，同时承载项目定位、依赖规则、测试细则、清理策略和完成门禁。内容虽然完整，但章节职责过多，无法直接表达项目的首要目的：通过从零实现 Agent Kernel 系统学习 Agent 框架。

本版本把学习目标确立为项目主线，以可运行、可测试、可解释的 Kernel 作为学习结果和工程证据。

## 3. 新增内容

- 明确核心定位为“通过实现理解 Agent 框架”。
- 增加概念理解、架构设计和工程实现三层学习目标。
- 说明从零实现相对于直接使用成熟框架的学习价值。
- 将模块确认、真实链路验证和累计回归解释为学习方法。
- 将第一阶段成果同时定义为学习成果和工程成果。

## 4. 修改内容

第一章阅读路径调整为：

```text
项目是什么
  -> 要学习什么
  -> 为什么从零实现
  -> 采用什么方法
  -> 当前做什么
  -> 最终得到什么
```

原第一章中的详细依赖禁令、真实模型验收细则、渐进式真实对话规则和清理清单不再重复展开，分别由架构、测试、维护与版本章节负责。

## 5. 受影响内容

- `DEV_SPEC.md` 第一章项目概述。
- `DEV_SPEC.md` 阶段 A 的规格确认记录。
- `DEV_SPEC.md` 当前开发规格版本记录。
- `docs/dev-spec/README.md` 当前版本和版本索引。
- Agent Kernel 重构设计记录中的项目目标与学习定位。

不改变：

- Agent、Workflow、Tool、Memory、Model、Runtime 六个核心原语。
- Kernel、Adapter、Application、Interface 的系统边界。
- 模块级渐进式真实对话验收规则。
- 当前阶段不得创建代码目录的实现准入门禁。
- 不读取、不兼容、不迁移旧项目的规则。

## 6. 兼容性与迁移

本版本只改变规格叙事、章节职责和项目目标表达，不改变公共协议或运行链路，因此不需要代码迁移，也不创建新的架构版本。

后续章节审查应继续采用同一原则：每章只承担明确职责，学习解释与工程约束保持关联，但不在多个章节重复展开同一细则。

## 7. 测试和验收

- 第一章能够独立回答项目是什么、为什么做、如何学习、当前做什么和最终得到什么。
- 只浏览一级与二级标题即可理解章节阅读路径。
- 六个核心原语、真实 Provider、累计真实对话和业务隔离等硬约束仍然存在。
- 详细架构和测试规则在后续对应章节中保持完整。
- 文档链接、标题层级和版本索引检查通过。

## 8. 架构版本影响

本版本不改变原语职责、依赖方向、目录边界或运行链路，不需要新增 `docs/architecture/versions/` 完整正文。
