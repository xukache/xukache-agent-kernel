## 2. 变更原因

本版本把同一设计里程碑内已确认的 Core、Execution、支撑协议、Applications 和 Interfaces 统一收敛为一份完整基线。目标是让规格可以直接驱动第一条 Kernel 纵向切片，而不是继续按模块堆叠孤立文档。

本版本同时吸收了对照参考 `MODULAR-RAG-MCP-SERVER/DEV_SPEC.md` 的对抗性审查结论：

- 明确跨模块契约、所有权和依赖方向。
- 明确端到端执行链路和第一条实现切片。
- 明确测试证据、任务依赖和验收 ID。
- 明确外围能力的归属，但不把 RAG、MCP、Dashboard 等应用技术迁入 Kernel。

`v0.5` 到 `v0.14` 的模块确认不作为独立版本保留；它们属于本次同一设计里程碑，已合并到本版本。

## 3. 设计决策

### 3.1 Core 原语

Kernel 只保留六个核心原语：

```text
Agent
Workflow
Tool
Memory
Model
Runtime
```

### 3.2 Execution 执行层

Execution 是运行支撑层，不是第七个 Core 原语：

```text
Context
Hooks
Guardrails
Retry
Cancellation
Streaming
```

它统一承载当前运行上下文、边界控制、重试、取消、流式输出和观测扩展。

### 3.3 分层关系

```text
Interface
  -> Application
      -> Workflow
          -> Agent
              -> Model
              -> Tool
              -> Memory
      -> Runtime

Adapter
  -> 实现 Kernel 公开协议
```

Kernel 不依赖业务、接口、Provider SDK 或具体运行时框架。

## 4. 变更范围

### 4.1 新增和明确的内容

- Execution 执行层及其六项运行支撑能力。
- 六个 Core 原语的职责、非职责和依赖方向。
- Prompt、状态、证据和外围能力的归属。
- Core Contract Matrix、真实模型第一条纵向切片和 `K-001` 至 `K-010` 验收矩阵。
- `K-01` 至 `K-07` 实施任务及其依赖关系。

### 4.2 受影响模块

| 模块 | 影响 |
|---|---|
| Core | 冻结六个原语的最小职责和替换边界 |
| Execution | 承载 Context、Hooks、Guardrails、Retry、Cancellation、Streaming |
| Adapters | 通过协议接入真实 Model Provider、In-memory Memory、Tool 和 Runtime |
| Applications | 承载业务 Prompt、规则、数据模型和业务组合 |
| Interfaces | 只负责外部输入、事件转发、结果序列化和错误映射 |
| QA / System | 采用契约测试、架构测试和纵向切片验收 |

### 4.3 依赖和实现顺序

```text
规格审查
  -> K-01 协议目录
  -> K-02 最小 Adapter
  -> K-03 Agent 闭环
  -> K-04 Runtime / Events
  -> K-05 Workflow
  -> K-06 Contract Tests
  -> K-07 第一个架构版本
```

## 5. 关键边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| `Agent` | 使用 Instructions、Model、Tools 和 Memory 完成智能任务 | Workflow 调度、底层存储、接口和生命周期 |
| `Workflow` | 组合步骤，控制顺序、分支、暂停和恢复 | 替代 Agent、实现 Tool、管理 Memory 存储 |
| `Tool` | 结构化输入、外部动作、结构化输出和明确错误 | 推理、路由、Prompt 和重试决策 |
| `Memory` | 跨运行上下文的读取、写入和检索 | Workflow 状态、Trace、UI 历史和业务数据库 |
| `Model` | Provider 无关的请求、响应、Tool Call 意图和 usage | Prompt 所有权、Tool 执行、Workflow 路由和业务规则 |
| `Runtime` | Agent / Workflow 的运行生命周期 | Agent 推理、业务流程、底层 Tool / Memory / Model 实现 |

### 4.1 Prompt 所有权

```text
Application
  -> 提供 Prompt 模板、Instructions 和版本
Agent
  -> 组装最终 Model Request
Execution
  -> 提供运行约束、Guardrails 和取消信号
Model
  -> 生成 Model Response
```

Prompt 不成为新的 Core 原语。

### 4.2 状态和证据边界

```text
Workflow     = 当前流程推进状态
Execution    = 当前运行生命周期
Memory       = 跨运行保留的上下文
Observability = 运行证据
```

这些内容不能互相冒充事实来源、恢复数据或 UI 历史。

## 6. 外围能力归属

| 能力 | 归属 | v0.15 范围 |
|---|---|---|
| Prompt | Application 配置 + Agent 请求组装 | 定义所有权，不实现业务 Prompt |
| Observability | Execution / Runtime 横切能力 | 只定义事件和最小收集器 |
| Evals | System / QA | 先验证 Kernel contract 和纵向切片 |
| Security | Execution Guardrails / Interface | 先定义权限、取消和敏感输入边界 |
| Integrations | Adapters | 先接入真实 Model Provider，其他外部能力保持最小实现 |
| RAG | Application / Integrations | 不进入 Kernel |
| Deployment | Product / Interface | 不进入第一阶段 |
| Triggers / Actions | Product / Interface | 不进入第一阶段 |

## 7. Core Contract Matrix

| 原语 | 最小输入 | 最小输出 | 主要错误 | 生命周期 | 替换点 |
|---|---|---|---|---|---|
| Agent | input、Instructions、Tools、Memory | output、tool_calls、usage、stop_reason | model、tool、policy、internal | run -> complete / fail / cancel | Agent 配置 |
| Workflow | workflow input、steps、条件 | step_results、output、stop_reason | step、branch、pause、resume | start -> step -> pause / finish | Workflow 实现 |
| Tool | 结构化 input、Execution Context | 结构化 output | validation、permission、timeout、execution | validate -> execute -> result | Tool Adapter |
| Memory | read / write / search 请求 | context items / write result | scope、storage、serialization | read / write / query | Memory Adapter |
| Model | Model Request | response、tool_call、usage | provider、timeout、format | request -> response / error | Model Adapter |
| Runtime | Run Request、Agent 或 Workflow | events、Runtime Result | runtime、cancel、timeout、internal | start -> execute -> pause / resume -> finish | Runtime Adapter |

具体字段 Schema、序列化格式和错误码在实现任务中冻结，但实现不得绕过替换点直接依赖具体基础设施。

## 8. 第一条纵向切片

固定实现一条无业务的最小闭环：

```text
Programmatic Interface
  -> Application Fixture
      -> 单进程 Runtime
          -> Execution
              -> Agent
                  -> Real Model Provider Adapter
                  -> In-memory Memory
                  -> 无副作用结构化 Tool
              -> Events 收集器
          -> Agent Result
```

真实模型是该切片的必选依赖，必须覆盖：

- 一次 Model 生成。
- 一次可选 Tool Call。
- 一次 Memory 写入和再次读取。
- 一次结构化结果返回。
- 成功、Tool 输入错误、取消和流式事件四类结果。

## 11. 兼容性与迁移

- 不兼容旧 `mvp` / `main` 项目的代码、状态、数据、Prompt、Tool、Runtime 和接口。
- 不提供旧模块别名、旧协议适配或旧数据迁移。
- 旧项目只作为旧分支保留，不是本版本的事实源。
- 第一条纵向切片只验证新 Kernel 语义，不承担旧业务迁移。

迁移策略：无迁移路径。旧项目继续从 `mvp` / `main` 分支使用；新 `architecture` 分支只按本版本从空白 Kernel 实现。

## 12. 已知限制

- 当前没有 Kernel 实现代码。
- 生产环境的 Model Provider 组合、多 Provider 路由、Memory 存储、Workflow 库、Trace 存储和外部接口尚未冻结；第一条纵向切片已固定使用当前真实模型配置。
- 当前第一条纵向切片使用 `ANANHU_REAL_MODEL` 配置的真实模型；未配置凭证、网络不可用或 `ANANHU_REAL_MODEL_SMOKE` 未开启时，真实模型验收无法通过。
- 业务 Application、RAG、MCP、部署和生产级安全策略不属于本版本交付范围。
- 具体字段 Schema、序列化格式和错误码需在实现任务中以测试先行方式冻结。
