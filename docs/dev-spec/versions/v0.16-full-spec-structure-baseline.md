## 2. 变更原因

v0.15 具备核心边界，但各章的具体化程度不一致，技术选型、测试、扩展和确认记录没有完全采用“目标、设计、流程、配置、验收、扩展”的组织方式。v0.16 统一第 1-10 章的结构粒度，并按 Kernel 的真实运行顺序组织实施，保证先看到真实 Agent 效果，再扩展 Workflow、测试、架构版本和业务层。

## 3. 架构组织调整

### 3.1 三层结构

```text
Core
  -> Agent / Workflow / Tool / Memory / Model / Runtime

Execution
  -> Context / Hooks / Guardrails / Retry / Cancellation / Streaming

Outside
  -> Application / Interface / Adapter
```

Execution 是 Runtime 的运行支撑，不是第七个 Core 原语。外围层负责组合、接入和对外交互，不能反向污染 Core。

### 3.2 配置链路与执行链路分离

配置链路：

```text
Application 或测试 Fixture
  -> 组装 Agent / Workflow
      -> 绑定 Model / Tool / Memory
  -> 交给 Runtime
```

执行链路：

```text
Interface 或测试入口
  -> Runtime.start
      -> Execution 初始化 Context
      -> Agent 或 Workflow
          -> Model
          -> Tool
          -> Memory
      -> Events / Runtime Result
```

### 3.3 测试 Fixture 与业务 Application 分离

第一条纵向切片使用：

```text
tests/integration/real_model_fixture
```

它只用于验证 Kernel，不承载工伤或其他业务。真实业务 Application 必须等真实 Agent 闭环和 Kernel 测试通过后再建立。

### 3.4 最小目录边界

只冻结稳定边界：

```text
src/
  agent_kernel/
    agent/
    workflow/
    tool/
    memory/
    model/
    runtime/
  adapters/
    model/
    memory/
    tool/
    runtime/
applications/
interfaces/
tests/
  contract/
  integration/
  architecture/
```

Execution 支撑能力只在 `runtime/` 内部按实际复杂度拆分，不为每个支撑名词创建新的 Core 目录。

### 3.5 第 5 章小节结构

第 5 章按参考项目的“架构图到落地验证”顺序组织：

```text
5.1 整体架构图
5.2 目录结构与交付清单
5.3 Core 模块设计
5.4 执行流程
5.5 配置驱动设计
5.6 扩展性设计要点
5.7 Core Contract Matrix
5.8 第一条真实模型纵向切片
```

每个 Core 模块都必须写清目标、输入、输出、步骤、边界、错误和验收，不再只保留一句职责描述。

## 4. 新实施顺序

```text
稳定六个 Core 的最小协议
  -> 接入真实 Model Provider
  -> 尽早跑通真实 Agent 闭环
  -> 补齐 Runtime / Workflow 控制语义
  -> 完成 Contract / Integration / Architecture Tests
  -> 发布第一个架构版本
  -> 再建立业务 Application
  -> 最后接入具体 Interface
```

真实模型验证必须前置，不能等所有外围能力完成后才第一次调用模型。

## 6. 兼容性与迁移

- 不改变六个 Core 原语及其公共协议。
- 不引入新的 Core 原语，不兼容旧 `mvp` / `main` 项目。
- 不提前建立业务 Application 或具体 Interface。
- 不覆盖 v0.15；本版本只记录规格结构和实施排期的增量修订，不改变六个 Core 原语。

## 7. 已知限制

- 当前仍没有 Kernel 实现代码。
- 真实模型 Smoke 依赖 `ANANHU_REAL_MODEL`、Provider 凭证、网络和 `ANANHU_REAL_MODEL_SMOKE=1`。
- 具体 Provider 组合、Memory 存储、Workflow 库和外部 Interface 仍在 Adapter / Application 阶段决定。
