| 字段 | 内容 |

## 2. 变更原因

原 v0.16 虽然要求真实 Model Smoke 和最终纵向切片，但模块实现仍可能主要依赖 Unit / Contract Test 验收。这样会让真实链路在后期才第一次完整组装：前面模块即使各自通过，仍可能无法在真实用户输入下协作。

本版本把真实对话验证前移到每个模块实现任务。模块只有同时通过协议测试和真实对话场景，才能标记完成。

## 3. 新增规则

### 3.1 双层验收

```text
Unit / Contract / Architecture
  -> 验证协议、边界、错误和依赖方向

Progressive Real Dialogue
  -> 验证真实用户输入经过当前累计链路后，
     当前模块承担职责并产生正确输出、事件或状态
```

Unit、Contract 和受控测试 Adapter 可以覆盖确定性失败路径，但不能替代任何模块的主要真实对话完成证据。

### 3.2 模块级门禁

每个模块实现任务必须：

1. 定义固定、低成本、可重复的真实用户对话输入。
2. 定义当前模块在累计链路中的具体职责。
3. 定义结构化输出、数字事实、Tool 参数、Memory 召回、事件或状态断言。
4. 使用真实 Model Provider 执行主要场景。
5. 运行新增场景和此前全部真实对话场景。
6. 真实 Provider 不可用时标记 `BLOCKED`，不使用 fallback。
7. 原始对话必须经过真实 Model / Agent 转换为模块输入，Fixture 不得预填语义结果。
8. 对应 Unit / Contract Test 与模块实现同步建立，不能推迟到最终验收阶段。

### 3.3 阶段级门禁

阶段出口必须运行当前阶段和此前阶段的全部 `RD-*` 场景。任何历史场景回归失败，当前任务和阶段都不能完成。

## 4. 场景范围

`DEV_SPEC.md` 定义 `RD-001` 至 `RD-012`：

| 范围 | 主要验证 |
|---|---|
| RD-001 | 真实 Model 结构化输出 |
| RD-002 | Agent 请求组装和结果 |
| RD-003 | 真实 Tool Call 闭环 |
| RD-004 | Memory 两轮写入和召回 |
| RD-005 | Runtime 生命周期和事件 |
| RD-006 | Workflow 条件分支 |
| RD-007 | Workflow 暂停恢复 |
| RD-008 | Streaming 增量与最终结果 |
| RD-009 | 真实运行中的取消 |
| RD-010 | Hooks 和 Guardrails |
| RD-011 | 无依赖 Workflow 步骤并行 |
| RD-012 | Retry 和幂等治理 |

版本文档不复制每个场景的完整输入和断言；完整定义以 `DEV_SPEC.md` 为准。

## 5. 实施顺序变化

旧顺序：

```text
全部 Core Protocol
  -> Adapters
  -> Agent
  -> Runtime / Workflow
  -> 最终纵向切片
```

新顺序：

```text
最小支撑协议 + Model Protocol
  -> 真实 Provider + RD-001
  -> Agent + RD-002
  -> Tool + RD-003
  -> Memory + RD-004
  -> Runtime / Execution + RD-005、RD-008 至 RD-010、RD-012
  -> Workflow + RD-006、RD-007、RD-011
  -> 全部合同、架构和真实对话累计验收
```

协议可以先冻结，但模块“实现完成”必须等待对应 RD 场景。

## 6. 受影响内容

- `DEV_SPEC.md` 的设计理念、完成定义、测试分层、验收矩阵、纵向切片、项目排期和实现准入门禁。
- 后续阶段 B-G 的五份正式实施计划。
- 真实模型测试 Fixture 的职责：从单一最终切片改为持续增长的累计真实链路。
- 每个模块任务的证据格式和完成状态。

不改变：

- 六个 Core 原语。
- Kernel、Adapter、Application、Interface 的依赖边界。
- 不兼容旧 `mvp` / `main` 的策略。
- 阶段 H 继续延期。

## 7. 测试和证据

每个 RD 场景至少保存：

```text
test_id
run_id
model_id
provider
raw_dialogue_input
expected_structured_assertions
actual_output_summary
events
usage
latency
error_type
retry_count
```

自然语言只验证必要语义锚点；数字、枚举、Tool 参数、scope、run_id、事件和终态使用精确断言。

## 8. 架构版本影响

本版本强化测试验收口径并调整实施顺序。根据当前架构版本规则，正式进入代码实现前必须在实现准入流程中确认首个完整架构版本的时点和正文；在目录拓扑与实现级契约未确认前，不创建不完整的架构快照，也不允许开始代码实现。
