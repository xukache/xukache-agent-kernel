## 完整架构

系统仍是工伤咨询领域 CLI Agent Harness。`ask`、`eval` 和 `version` 继续通过框架中立的
`WorkflowRuntime` 工作；`chat` 直接进入 Textual TUI，不保留旧逐行交互模式，也不新增并行的
`tui` 命令。默认运行时仍为 `LangGraphWorkflowRuntime`，Native 实现继续用于回归，两者共享项目阶段、
reducer、CapabilityGateway、ModelGateway、TraceEvent、Usage 和 Eval 协议。

```text
NativeWorkflowRuntime -----|
                           +-> shared stage wrapper -> RunEventSink
LangGraphWorkflowRuntime --|             |                 |
                                         |                 +-> TraceRecorder sink
                                         |                 +-> asyncio.Queue -> Textual TUI
                                         +-> ObservableModelGateway -> provider
                                         +-> CapabilityGateway -> ToolExecutor
```

Textual 与 Rich 类型只能存在于 `cli/tui/` 展示层。领域、应用、Agent、Tool、Prompt、Eval、Runtime
公共协议不得导入 Textual，也不得把 LangGraph event、message、checkpoint、channel 或 Command 投影到
TUI。业务 trace 继续是持久化运行证据的事实来源。

## 单栏 Textual Chat TUI

`ananhu-agent chat` 使用单栏会话布局，按轮展示用户消息、可折叠运行检查器、AI Markdown 答复和本轮
聚合 Usage。运行检查器实时展示节点、模型、工具和校验状态；每个输入、输出及 provider 显式
reasoning 都可独立展开。单会话一次只允许一个运行中请求，运行期间禁止重复发送，但允许浏览历史。

旧 chat 能力迁移为 TUI action 或 modal：新会话、帮助、上下文摘要、最近 trace、badcase、正负反馈、
清屏、重试和退出。`Ctrl+R` 保留原 `request_id` 并创建新 `run_id`。非 TTY 或 `TERM=dumb` 时
`chat` 以退出码 2 明确失败，不回退逐行模式；其他 CLI 命令不受 TTY 门禁影响。

## RunProgressEvent 协议

系统新增唯一的框架中立实时协议 `RunProgressEvent`。它是按 `kind` 判别的 Pydantic 联合，每种事件使用
独立 payload 类型，至少覆盖：

```text
run_started | node_started | node_finished | node_failed
model_started | model_finished | model_failed
capability_started | capability_finished | capability_failed
run_cancelled | run_finished
```

公共身份字段为 `run_id`、`request_id`、`session_id`、`node_id`、`logical_call_id`、`attempt`、
`sequence_no` 和时间。节点输入输出只能来自项目 Pydantic 类型的受控视图，禁止携带 LangGraph state
或 provider 原始响应。共享阶段包装器统一发布节点生命周期，ObservableModelGateway 发布模型生命周期，
CapabilityGateway 发布工具生命周期；Agent 不依赖事件 sink。

事件区分 `public_payload` 和 `transient_payload`。公共部分可经显式 `to_trace_event()` 安全投影，瞬态
部分设置 Pydantic 序列化排除，只允许当前进程展示所需的裁剪脱敏 Prompt、message、reasoning 和详细
JSON。Trace sink 不得通过通用 `model_dump()` 持久化事件。

## Sequence、Gap 与终止屏障

`CompositeRunEventSink.publish()` 是 `sequence_no` 的唯一分配点。生产者发布未编号事件；组合 sink 在
按 run 加锁的临界区中原子递增，再将同一个已编号事件依次交给 trace 和 queue。Runtime、模型和能力
网关不得维护独立计数器。首版 queue 是同一 event loop 的无界 `asyncio.Queue`，禁止丢事件。

消费者按 run 隔离状态，重复或旧序号幂等忽略。收到未来序号形成 gap 时，立即把本地展示标记为
`event_sequence_gap` 并停止 spinner；随后只排空该 run 事件，`run_finished` 仅确认队列清理，不能覆盖
gap 失败。`run_finished` 是唯一 run 级终止屏障，必须在全部前序事件入队后发布且每个 run 只发布一次。

## 取消协议

Runtime 最外层 `try/except/finally` 是 `run_cancelled` 和唯一 `run_finished` 的生产者。用户在运行中退出时，
先发布 `run_cancelled`，随后发布 `run_finished(status=cancelled, stop_reason=user_cancelled)`。工作流协议
增加 `RunStatus.CANCELLED` 和 `StopReason.USER_CANCELLED`。取消时只携带已经完成调用的已知 Usage，不用
空对象伪造尚未产生的数据。

Textual 取消 worker 后最多等待 2 秒消费终止屏障；超时只显示本地退出错误并回收 worker，不伪造业务
事件，也不得留下 spinner 或后台任务。

## ModelGateway、Reasoning 与 Usage

v0.6 的 Provider/Profile 目录、OpenAI-compatible 最小协议、结构化 JSON Schema 校验和密钥边界保持
有效。组合根在具体 ModelGateway 外装配 `ObservableModelGateway`，它收到完整 `ModelRequest` 后发布真实
模型输入视图，并在完成或失败时发布输出、Usage 和错误摘要。阶段内重复模型埋点迁移到该装饰器。

OpenAI-compatible adapter 只解析 provider 响应中显式存在且类型为字符串的
`message.reasoning_content`。未返回、null 或空字符串归一为 `None`；其他类型返回 provider 响应格式
错误。`ModelResult.reasoning_content` 必须设置 `exclude=True, repr=False`。运行事件的瞬态 payload 只
保存裁剪脱敏后的内存视图，公共投影只记录是否存在、原始字符数和是否裁剪。Agent、WorkflowState、
TaskState、RunReport、SessionState、trace、badcase、eval 和 differential artifact 均不得保存、解释或
依赖 reasoning 原文。

`ModelUsage` 增加 `reported: bool`，区分 provider 报告零值与未报告。单轮聚合只求和所有成功且
`reported=True` 的 ModelResult；任一成功 provider 调用未报告时显示 `tokens unknown`，速度显示 `--`。
Fake 固定为 `reported=False, usage_source=fake`，纯 Fake 轮次显示 `fake · 0 tokens`。失败且没有
ModelResult 的尝试不计 token；provider total 与分项不一致时保留原值并标记 inconsistent。总耗时覆盖
完整 Runtime，输出速度使用已报告的总输出 token 除以模型调用累计耗时。

## Capability 与 Other 路径

`CapabilityRequest` 补充 `run_id`，保证工具事件归属于唯一运行；ToolExecutor 的权限、schema、超时、
幂等、重试和 trace 治理保持不变。实时事件只展示治理后的实际参数、结果、状态、fallback 和耗时。

`other` 意图在 plan 阶段选择确定性无工具路径，execute 不产生 capability 请求，compose 生成能力边界
说明，之后仍通过 safety 并以 completed 结束。问候返回固定欢迎文案；非问候类输入邀请用户改写为
工伤相关问题。所有 StopReason 必须映射为 `final_answer`、`clarification_question` 或
`error_message` 之一，CLI 不得显示空白回复。Native/LangGraph 必须保持业务结果和事件语义等价。

## 数据、脱敏与观测

实时公共投影遵循最小必要保存原则：递归移除或替换 API key、authorization、cookie、token、password、
代理凭据、URL query/header 中的敏感值，并裁剪长 Prompt、工具结果和文档正文。瞬态内容在新会话、
清屏和退出时释放。TraceRecorder 只能接收事件类型定义的显式安全投影；LangGraph/LangSmith 仍只作为
补充诊断，不能替代项目 trace。

Eval 增加事件顺序、唯一终止屏障、gap、跨 run 隔离、reasoning 零持久化、Usage reported、other 无
工具路径、Textual Pilot、80x24 布局、真实 PTY、非 TTY 门禁和 secret canary 验收。Native/LangGraph
差分继续比较项目结果、状态、能力参数和 trace 语义，不比较框架内部事件文本。

## 相对 v0.6 的差异

1. `chat` 从逐行 Typer 循环替换为单栏 Textual TUI，旧命令能力迁移为 action/modal。
2. 新增框架中立 `RunProgressEvent`、组合 sink、单点 sequence 分配、gap 失败和唯一终止屏障。
3. 新增取消状态与 `user_cancelled` 停止原因，并定义 worker 回收等待边界。
4. 新增 ObservableModelGateway、显式 reasoning 瞬态路径和 Usage reported 语义。
5. CapabilityRequest 增加 run 身份，`other` 使用确定性无工具非空回复路径。
6. 新增 Textual、Pilot、PTY、reasoning 持久化扫描和 secret canary 验收范围。

## 兼容性与迁移策略

`ask`、`eval`、`eval --runtime both` 和 `version` 的调用方式、输出契约及非 TTY 行为保持兼容。Native
与 LangGraph 继续实现同一个 WorkflowRuntime；事件端口默认提供 no-op sink，因此非交互调用方无需消费
实时事件。现有 trace schema 通过显式投影兼容扩展，不迁移历史 trace。v0.6 模型目录和旧环境变量兼容
路径保持有效。

旧 chat 的逐行输入协议属于有意移除的交互兼容性；脚本不得继续依赖它，应使用 `ask` 或 `eval`。
reasoning 和实时 queue 只在进程内存在，不建立新的持久化兼容承诺。

## 任务计划与验收标准

设计入口为 `docs/superpowers/specs/2026-07-10-textual-chat-tui-design.md`，实施入口为
`docs/superpowers/plans/2026-07-10-textual-chat-tui.md`。验收要求 `chat` 直接进入 Textual TUI；事件
sequence 单调且 gap 显式失败；终止屏障唯一；reasoning 原文不进入任何持久化产物；Usage 对 fake、
缺失和混合场景口径明确；`other` 双运行时无工具且回复非空；Pilot、PTY、全量 pytest 和双运行时差分
均通过；v0.6 正文无修改。

## 已知限制

首版不支持模型 token 级流式输出、broker、跨进程订阅、事件丢弃、剪贴板复制、片段保存或配置热重载。
reasoning 仅兼容 OpenAI-compatible `message.reasoning_content`。Textual TUI 需要支持 ANSI 和交互输入的
终端，CI 使用 Pilot/headless；超大 JSON 只展示裁剪视图。当前仍没有 HTTP API、WebSocket 或前端页面，
真实 KnowledgeGateway、生产级 checkpoint 和复杂并行不在本版本范围。
