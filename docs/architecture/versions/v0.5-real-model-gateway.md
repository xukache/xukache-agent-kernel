## 完整架构

系统仍是工伤咨询领域 CLI Agent Harness。CLI 与 Eval 只依赖框架中立
`WorkflowRuntime`；默认实现为 `LangGraphWorkflowRuntime`，Native 实现保留用于回归。
两种 Runtime 共享阶段服务、项目 reducer、CapabilityGateway、ModelGateway、TraceEvent 和
Eval 数据，不持有 provider SDK 类型。

```text
NativeWorkflowRuntime -----|
                           +-> application stage -> ModelGateway
LangGraphWorkflowRuntime --|                         |
                                                     +-> FakeModelGateway
                                                     +-> OpenAICompatibleModelGateway
                                                            |
                                                            +-> /chat/completions

ModelRequest -> ModelResult | ModelGatewayError
                       |
                       +-> project trace + UsageRecord fields
```

业务阶段保持 `understand -> merge_facts -> validate_facts -> clarify |
resolve_jurisdiction -> plan -> execute -> validate_evidence -> compose -> safety -> complete`。
本版本只替换意图识别阶段的模型边界，不改变业务状态机、reducer、CapabilityGateway 或
Native/LangGraph 的调度职责。

## ModelGateway 协议

公共端口使用项目 Pydantic 类型并提供 async `generate_structured()`。`ModelRequest` 至少携带
运行关联 ID、node、logical call、模型 profile、Prompt 引用和渲染后文本；`ModelResult`
包含结构化输出、provider、model、finish reason、token usage、估算费用、延迟和尝试次数。
供应商响应、HTTP 客户端和 SDK 类型不得进入 Agent、application 或 Runtime 公共协议。
结构化输出使用项目提供的 JSON Schema Draft 2020-12 校验，类型、枚举、范围和嵌套结构不合法时
统一返回 `output_schema_error`，不得先记录为成功模型调用。

错误统一归类为配置、鉴权、限流、超时、provider、响应格式和输出 schema 错误。错误对象不得
包含 API key 或完整敏感响应体。是否重试由 gateway policy 决定，logical call ID 在物理重试间
保持不变，attempt 单独增加。

## Provider 与配置

真实适配器使用 OpenAI-compatible `POST /chat/completions`，采用 Bearer token、JSON object
结构化输出和 provider usage 字段。配置由 `RuntimeSettings` 集中读取：profile 声明
`provider=openai_compatible`、`model`、`temperature` 和 `timeout_seconds`，密钥与 base URL
使用独立环境变量。默认 profile 继续使用 Fake，不存在 key 时不会访问网络。

真实 smoke 必须同时显式设置启用开关、API key、base URL 和真实模型 profile。常规 contract
tests 使用 Fake 或受控 HTTP transport；未启用 smoke 时测试 skip，而不是失败。禁止把 key 写入
profile、trace、usage artifact、测试 fixture 或版本库。

## Trace 与 Usage

模型调用写入项目 `model_started`、`model_finished` 或 `model_failed` 事件，并关联 run、request、
runtime、node、logical call、attempt、profile、provider、model 和 Prompt 版本。成功 usage 至少区分
input、output、cache 和 total token，费用只在配置了价格时估算，并明确币种。RunReport 汇总项目
ModelResult，不依赖 provider SDK 或 LangSmith 计费口径。

Fake 与真实调用通过 `usage_source=fake|provider` 分开报告。Fake token 和费用固定为零，只服务确定性
回归；真实 smoke 结果不得与离线 eval 汇总为同一质量指标。

## 相对 v0.4 的差异

1. 新增框架中立 `ModelRequest`、`ModelResult`、`ModelUsage`、`ModelGatewayError` 和 async 端口。
2. 将确定性模型迁移为 FakeModelGateway contract 替身。
3. 新增通用 OpenAI-compatible HTTP adapter 和显式 opt-in smoke。
4. 模型 trace 从单一 `model_called` 扩展为 started/finished/failed，并在 RunReport 汇总 usage。
5. Native/LangGraph 继续复用相同阶段服务和同一个 gateway 装配入口。

## 兼容性与迁移策略

默认配置仍为 Fake，因此现有 CLI、离线 eval 和双运行时差分结果保持确定性。旧 `ModelRouter`
profile 查询语义保留在新的 registry/组合根中，但 Agent 不再依赖 Fake 客户端具体类型。历史
`model_called` trace 继续作为旧 schema 证据保留，不原地迁移。

## 任务计划与验收标准

实施入口为 `docs/superpowers/plans/2026-07-10-framework-neutral-langgraph-evolution.md` 的任务 32。
验收要求 ModelGateway contract tests 通过；Native/LangGraph 使用同一 gateway；无 key 的 CI 不失败；
显式配置后可运行真实 smoke；fake 与 provider usage 分开记录；公共模块不导入 LangGraph 或 provider SDK。

## 已知限制

OpenAI-compatible 方言在结构化输出、usage 和错误体上存在差异，本版本只承诺已定义的最小兼容
子集。真实 smoke 只验证连接、协议解析和证据记录，不证明模型业务质量。真实 KnowledgeGateway、
完整咨询 smoke、生产级重试/fallback、流式输出和价格目录仍属于后续任务。
