## 完整架构

系统仍是 CLI Agent Harness。`ask`、`eval`、`chat` 和 `version` 通过项目协议工作；默认
`LangGraphWorkflowRuntime` 与显式 `NativeWorkflowRuntime` 共享阶段服务、reducer、
CapabilityGateway、ModelGateway、KnowledgeGateway、TraceEvent、Usage 和 Eval 协议。

```text
NativeWorkflowRuntime -----|
                           +-> shared stages -> CapabilityGateway -> ToolExecutor
LangGraphWorkflowRuntime --|       |           KnowledgeGateway -> policy-corpus.v1
                                   |           ModelGateway -> provider/fake
                                   +-> TraceRecorder / RunProgressEvent -> CLI/TUI
```

LangGraph 只调度项目阶段。KnowledgeGateway、EvidenceItem、政策元数据和 lexical 评分不进入
LangGraph 专有协议。

## KnowledgeGateway 与政策语料

`KnowledgeGateway` 是框架中立 async 端口，输入 `KnowledgeQuery`，输出
`KnowledgeSearchResult`。结果中的 `EvidenceItem` 至少包含：

```text
evidence_id
document_id
title / article / content
tenant / province / city
effective_from / effective_to
review_status / audience_roles / source_type
document_version / source_url
corpus_version / evidence_hash
retrieval_method / lexical_score
citation
```

当前基础设施实现是 `LexicalKnowledgeGateway`，读取 `policy-corpus.v1` JSONL。每条语料必须拥有
tenant、jurisdiction、有效期、审核状态、受众、来源类型、文档版本、HTTPS source URL 和可计算
证据 hash。默认只允许 `approved`、`official` 和目标 audience 的文档。

检索顺序固定为：

```text
trusted metadata filter -> lexical baseline -> EvidenceItem -> citation validation
```

当前 lexical baseline 使用语料关键词、标题和条款短语做可解释评分。向量检索、融合和 reranker
属于未来候选，必须等 RAG eval 证明 lexical baseline 的缺口后再引入。

## Jurisdiction 安全边界

`RunRequest.trusted_jurisdiction` 优先；缺省时由项目确定性解析器从用户原文识别省级范围。
模型返回的地区槽位只属于候选案件事实，不得覆盖 `ctx.request` 的可信地区。若用户提到地方
地区但没有可信 jurisdiction，KnowledgeGateway 返回无结果并标记 `no_trusted_jurisdiction_match`，
不把地方政策扩展到全国范围。

## 兼容与组合根

现有 `PolicyRAGTool` 保留为 `ToolExecutor` 的兼容能力名，handler 只将旧 payload 转成
`KnowledgeQuery`，再调用同一 `LexicalKnowledgeGateway` 的同步适配。`create_default_runtime()`
允许注入 KnowledgeGateway；Native 与 LangGraph 可使用同一个实例，CapabilityGateway 仍拥有权限、
幂等、超时和 trace 治理。

旧 `policy_fixtures.jsonl` 仍支持显式 fixture 回放；默认组合根使用 `policy-corpus.v1.jsonl`。
旧答案聚合读取兼容的 `documents` 投影，citation 额外保留 Evidence ID、地区、版本和 source URL。

## RAG Eval 与观测

`RAGEvalRunner` 使用 `rag_cases.jsonl` 和 `rag_cases_no_result.jsonl`，单独报告：

- Recall@K、MRR。
- citation support rate。
- trusted filter rate。
- no-result rate 和 `fabrication_allowed=false`。
- 每条 case 的 expected/retrieved document ID 与 no-result reason。

Trace、RunReport、Badcase 和 Eval artifact 不得用模型常识替代 EvidenceItem。无结果必须进入保守
回答路径；答案结论必须能够回指 Evidence ID。

## 相对 v0.7 的差异

1. 新增 KnowledgeGateway 端口、LexicalKnowledgeGateway 和结构化 EvidenceItem。
2. 新增 `policy-corpus.v1`，将政策有效期、审核、版本、来源和证据 hash 纳入检索事实源。
3. PolicyRAGTool 改为 KnowledgeGateway 兼容适配，不改变现有 CapabilityGateway 治理。
4. 模型地区槽位不再覆盖可信检索范围，增加确定性用户地区解析。
5. 新增 RAG 专项 eval 和无结果不编造的验收口径。

## 兼容性与迁移策略

`ask`、`eval`、`eval --runtime both` 和 `chat` 入口保持兼容。旧工具的 `documents` 输出继续存在；
下游可渐进读取 `evidence_id`、`document_version` 和 `source_url`。未来向量召回只能替换
KnowledgeGateway 基础设施实现，不能改变公共查询、EvidenceItem、引用校验和专项评测契约。

## 任务计划与验收标准

实施计划为 `docs/superpowers/plans/2026-07-11-knowledge-gateway-policy-baseline.md`。

验收要求：

- KnowledgeGateway、语料质量和 RAG eval 测试通过。
- 可信元数据在 lexical 召回前生效。
- EvidenceItem 能回指文档、条款、来源 URL、版本和证据 hash。
- 无结果不生成虚构政策依据。
- Native/LangGraph 通过组合根复用同一 KnowledgeGateway，离线 differential eval 等价。

## 已知限制

当前语料是小规模、人工审核的离线政策基线，不是持续更新的生产知识库；当前只启用 lexical
baseline，不支持 embedding、vector store、fusion、reranker、自动审核和在线抓取。真实模型咨询
Smoke Eval 延后至任务 34，不能把本版本离线 RAG 指标描述为生产质量。
