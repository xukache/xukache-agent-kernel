## 完整架构

系统是工伤咨询领域 CLI Agent Harness。CLI 与 Eval 只依赖框架中立 `WorkflowRuntime`；默认实现为 `LangGraphWorkflowRuntime`，Native 实现保留用于回归。两种实现共享 `RunRequest`、`WorkflowState`、`StatePatch`、项目 reducer、阶段服务、CapabilityGateway、TraceEvent 和 Eval 数据。

```text
Eval cases + same RunRequest
       |---------------------------|
       v                           v
NativeWorkflowRuntime      LangGraphWorkflowRuntime
       |                           |
       +---- WorkflowResult -------+
       +---- WorkflowState --------+
       +---- project TraceEvent ---+
                    |
                    v
       RuntimeDifferentialRunner
                    |
                    v
       runtime-differential.v1 artifact
```

业务阶段保持 `understand -> merge_facts -> validate_facts -> clarify | resolve_jurisdiction -> plan -> execute -> validate_evidence -> compose -> safety -> complete`。Reducer 是状态合并唯一事实源；CapabilityGateway 是能力治理唯一入口；项目 TraceEvent 是过程比较事实源。差分执行器不得读取 LangGraph 内部 graph state、task、checkpoint 或事件类型。

## 差分协议

每个 case 使用相同 run/request/session 身份和用户输入分别执行两种 Runtime，并比较：

1. `WorkflowResult`、RunStatus、StopReason 和最终回答/追问。
2. 最终 `WorkflowState` 的事实、意图、执行计划、能力结果、证据、验证和安全结果。
3. TraceEvent 的事件类型、phase、node、logical call、attempt 和业务 payload。

允许忽略字段仅为 runtime 名称/版本、随机 TraceEvent ID、创建时间、毫秒延迟和节点内部事件顺序。业务 ID、调用参数、证据 ID/内容、安全结果和事件集合不允许不同。Agent 产生的 logical tool call ID 基于 request 和能力保持稳定，保证两次执行可关联。

`runtime-differential.v1` artifact 包含总 case 数、等价/差异数以及每个 case 的 request、比较事件数和逐字段 mismatch。存在禁止差异时 `eval --runtime both` 返回非零退出码。两种 Runtime 使用隔离目录，避免持久化状态和幂等缓存交叉污染。

## 相对 v0.3 的差异

1. 新增 `RuntimeDifferentialRunner` 和结构化 mismatch/report schema。
2. 新增 CLI `eval --runtime both`，支持 30 条现有 eval case 的双运行时验收。
3. Tool logical call ID 从随机 UUID 改为同请求和能力下稳定 ID。
4. 明确差分允许字段白名单，业务字段默认全部严格比较。

## 兼容性与迁移

默认单 runtime CLI、`WorkflowRuntime.invoke()`、业务状态和 JSONL TraceEvent schema 不变。Logical call ID 的值格式变化，但语义仍是同一逻辑能力调用的稳定关联 ID；旧 trace 无需迁移，只作为历史证据保留。v0.3 文档保持只读归档。

## 任务计划与验收

实施入口为 `docs/superpowers/plans/archive/2026-07-10-framework-neutral-langgraph-evolution.md` 的任务 31。验收要求 30 条 eval case 无禁止差异，差分 artifact 可定位字段，EvalRunner/差分执行器不读取 LangGraph 内部对象。

## 已知限制

差分证明当前 fake model、fixture knowledge 和确定性工具下两种 Runtime 语义一致，不证明真实模型或真实政策知识质量。当前无 checkpoint、interrupt、并行、HTTP、WebSocket 或前端；真实 ModelGateway、KnowledgeGateway 和真实咨询 smoke 属于后续任务。
